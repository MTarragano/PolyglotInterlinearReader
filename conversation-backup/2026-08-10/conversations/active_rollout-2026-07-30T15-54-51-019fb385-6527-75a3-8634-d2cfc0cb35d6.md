## Composer workflow

The guided Composer should ask only about missing or ambiguous information.

1. **Sources**

   Audio/video, original text, translations, annotation spreadsheets, JSON, SRT/VTT, or a Polyglot Reader document.

2. **Language and structure**

   Language, script direction, sentence/token divisions and punctuation attachment.

3. **Timing**

   Use existing cue times, import subtitle timings, run transcription/forced alignment, or allow manual correction. Timing source, confidence and provenance must be retained.

4. **Linguistic annotations**

   Transliteration, morphology, morphemes, gloss, lexical translation, lemma, root, pattern/form and other dynamic annotation rows.

5. **Transliteration scheme**

   Select a saved scheme and its display transformation.

6. **Visible rows**

   Start from the user’s Polyglot Reader profile, then permit per-project overrides.

7. **Page fitting and typography**

   Show representative short, medium and long interlinear pages; suggest a fit rather than requiring the user to understand video typography.

8. **Outputs**

   MP4, HTML preview, SRT/VTT, JSON, audio lyric formats and eventually a portable lesson package.

9. **Validate and render**

   Warn about missing annotations, overflows, questionable alignment, unavailable fonts and provisional machine-generated data.

## Profiles and defaults

Use a predictable precedence:

```text
system defaults
  → user global profile
  → per-language profile
  → project settings
  → output-specific overrides
```

Therefore the main Reader and standalone Composer can share settings without making them inseparable.

Instead of asking “how many lines should be squeezed onto each screen?”, present:

- **Fit policy**: Automatic, Fixed or Maximum density.
- **Preferred blocks per page**: normally 4.
- **Minimum blocks per page**: normally 2.
- Minimum and maximum font sizes.
- Minimum row and token gaps.
- Whether wrapping is allowed.
- Overflow policy: reduce font, reduce block count, wrap or warn.

## Transliteration Schemas

This should be a first-class sibling package because it serves the Reader, Media Studio, import/export and dictionaries—not merely MP4 rendering.

A schema must separate four things:

1. **Canonical stored value**

   Normal logical transliteration used for search, export and accessibility.

2. **Conversion rules**

   How source script, phonemes or morphemes map to transliteration.

3. **Segmentation and linguistic spans**

   Syllables, tones, roots, stems, prefixes, particles and suffixes.

4. **Didactic presentation**

   Mirroring, capitalization, bolding, colour, spacing, tone diagrams and other learner-facing transformations.

Presentation transformations must never corrupt the canonical stored form.

### Chinese

Pinyin should be structured by syllable:

```json
{
  "text": "nǐ",
  "base": "ni",
  "tone": 3,
  "contour": [5, 1, 4]
}
```

That would permit:

- Normal tone diacritics.
- Tone numbers.
- Colour-coded tones.
- Pinyin syllables vertically positioned against an abstract tone stave.
- Eventually an actual pitch trace derived from aligned audio.

The abstract lexical tone contour and measured speaker pitch must remain distinct: one describes the dictionary tone; the other describes what occurred in the recording.

Radical/component colouring is not really transliteration. It should be a separate `glyph_decomposition` annotation layer, rendered through styled text, SVG or licensed specialist fonts, with ordinary Unicode characters retained as the fallback.

### Arabic

Store normal transliteration, then optionally apply a grapheme-aware didactic mirror during display. Do not reverse raw Unicode or overwrite the stored value.

Arabic morphology should expose spans such as:

```json
[
  {"role": "prefix", "text": "..."},
  {"role": "root", "text": "..."},
  {"role": "pattern", "text": "..."},
  {"role": "suffix", "text": "..."}
]
```

A presentation schema could then select:

- Root letters bold or uppercase.
- Particles in a different weight.
- Thin spaces at morpheme boundaries.
- Prefix/root/suffix colours.
- Underlines or outlines for non-colour accessibility.
- Mirrored Latin transliteration.
- Separate rows for lexical translation, grammatical gloss, root and verb-form pattern.

These should be genuinely separate dynamic rows, not overloaded into one “gloss” string.
